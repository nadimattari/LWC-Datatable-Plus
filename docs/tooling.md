## Formatting

JavaScript, HTML, CSS, JSON, Markdown, Apex classes, and Apex triggers are formatted with Prettier using a gofmt-inspired configuration: tabs for indentation, tab width 4, no semicolons, single quotes, no trailing commas, no bracket padding, and a print width of 100. Apex still requires statement semicolons because the language parser requires them. Salesforce XML manifests are generated by the CLI and are not passed through Prettier.

Sources:

- https://prettier.io/docs/en/options.html
- https://github.com/dangmai/prettier-plugin-apex#configuration

## Lightning Web Component testing

LWC unit tests run through `@salesforce/sfdx-lwc-jest`, which supplies the Jest preset, LWC transformer, resolver, serializer, and base component stubs. The default config is imported into `jest.config.js` and extended with test-path exclusions and an 80% global coverage threshold. The coverage glob is overridden to `force-app/main/default/lwc/**/*.js` because the extensionless default from the preset collected no files in this project, producing an empty 0% report that silently bypassed the threshold.

Source:

- https://github.com/salesforce/sfdx-lwc-jest#overriding-jest-config

## Service-boundary implementation

The Apex query service applies the verified patterns above. Object and field names are resolved through schema describes before they enter dynamic SOQL, field accessibility is checked from the describe results, and queries run with `AccessLevel.USER_MODE` from a read-only `@AuraEnabled(cacheable=true)` method. Search text is supplied through `Database.queryWithBinds` bind variables. The request, response, and error DTOs are top-level classes with `@AuraEnabled` properties. Expected failures are returned in the envelope with documented error codes; unexpected exceptions are logged without client details.

## Query-controls implementation

The query controls use `lightning-input type="search"` with a required `label`, `onchange` for each value change, and `oncommit` for a finished edit such as Enter. Search requests are delayed with `setTimeout`; each new value clears and restarts the timer, and disconnection clears any pending timer. `lightning-button` supplies labelled, keyboard-reachable first, previous, next, and last controls; `disabled` communicates boundary state to assistive technology. The page status uses `aria-live="polite"` so assistive technology can announce page changes.

Internal `searchrequest` and `pagerequest` events use `CustomEvent` with a fresh `detail` object. Their names are lowercase and do not start with `on`. They bubble to the immediate parent but do not cross the shadow boundary because only the owning shell handles them.

The LWC lint rule `no-async-operation` is suppressed only at the debounce timer. The rule guidance targets DOM timing that belongs in lifecycle hooks; user-input debouncing needs a cancellable timer, which this component clears on commit and disconnect.

## Task 1 smoke slice

Two small, production-shaped files prove that the formatter, LWC test runner, deploy, and Apex test runner are wired correctly:

- `datatablePlusUtils` is a JavaScript utility module with a unit test for normalizing row input.
- `DatatablePlusValidation` is an Apex input-validation helper with tests for the accepted and rejected paths.

These are real helpers that later feature slices can call; they are not placeholder implementations.

Apex tests cannot inspect `AuraHandledException` messages, so `DatatablePlusValidationTest` asserts the exception type rather than the sanitized message.
